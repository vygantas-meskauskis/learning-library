# Becoming an AI-Native Designer

### A practical guide for mid-to-senior UX/UI designers (October 2026)

> **Who this is for:** a designer who already knows UX/UI and Figma well and wants to work the way the best AI-native designers work today. You'll learn to build design systems that both people and AI can use, connect Figma to code without writing any code yourself, and use AI every day without lowering your standards.

---

## What "AI-native" means here

An AI-native designer isn't someone who uses ChatGPT a lot. It's someone whose **work is set up so AI can amplify it**:

- Their **design system** is structured so that AI tools build *with* it rather than around it.
- Their **knowledge** (users, rules, standards) is written down where AI tools can read it.
- They **delegate** drafts, variations, busywork and code to AI, and keep **judgment, taste and decisions** for themselves.
- They know **where everything lives and who (or what) does what**: Figma, the AI tools, the developers' code, and the files that connect them.

This guide teaches that setup and those habits.

---

## How the guide works

**One story runs through every chapter.** You join **Movewell**, a startup with a mobile app (iOS and Android) for booking local fitness and wellness classes such as yoga, pilates, spin, climbing intros and sound baths. You're the new **senior product designer**. Along the way you will:

1. Imagine the **ideal setup** if we started today (greenfield).
2. Face **reality**: an inherited, messy Figma file and an app that drifted from it.
3. Rebuild the design system so that people *and* AI can use it.
4. Connect Figma to the developers' code, and let an AI agent build screens from your designs.
5. Use the system every day with AI: designing, prototyping, research.
6. Design the app's first **AI feature**.
7. Learn how to work with developers and PMs in this new setup.

Every chapter has the same structure:

| Part | What it gives you |
|---|---|
| 📖 **Story** | What happens at Movewell, so concepts have a concrete context |
| 🧠 **Concepts** | The ideas explained plainly |
| 🧾 **Real artifacts** | Actual prompts, outputs, file excerpts and decisions from the story |
| 🗺️ **Diagram** | Who does what, where things live, how they flow |
| 🧰 **Helpers** | Copy-ready prompts, checklists and templates, and how to make them permanent |
| 🧪 **Try it yourself** *(optional)* | A small experiment you can do in your own Figma and ChatGPT |
| ✅ **Recap** | Three lines to remember |

Each chapter takes 20–40 minutes to read.

## Your tools

You already have the two tools this guide is built around:

| Tool | What you'll use it for |
|---|---|
| **Figma** (paid, Full seat) | Variables, components, libraries; the **Figma agent** (on-canvas AI); **Figma Make** (prompt-to-interactive-prototype); the **Figma MCP server** (lets AI agents read and write Figma) |
| **ChatGPT** (paid) | Daily thinking partner, research and writing; **Projects** to hold your product context; **Codex** (OpenAI's coding agent, part of paid ChatGPT plans) to turn designs into working code without writing it yourself |

Other tools are mentioned only where AI-native designers genuinely use them (see [Chapter 16](chapters/16-toolkit.md#-other-tools-worth-knowing)).

> 🔧 **Tool facts change fast.** Everything here was checked against official docs in October 2026. When a detail is likely to change (menus, plans, beta features), it's marked 🔧. The *concepts* are what you're really learning.
